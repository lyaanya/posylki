# Варианты дизайна главной страницы — черновые концепты

10 августа 2026. Через `/impeccable`, на основе `research/competitor-references/` и `docs/tz/epic-00-overview.md` + `epic-02-design-system.md`. Визуальная система (цвета, шрифты, лого VEZY) зафиксирована и не менялась между вариантами — сравниваются только **структуры**, не палитры.

Формат — статичные JPEG-мокапы первого экрана, не код. HTML-исходники лежат рядом (`a-search-first.html` и т.д.) — можно открыть в браузере и покрутить.

## A — Search-first (`a-search-first.jpg`)

Референс: Aviasales, BlaBlaCar. Форма поиска — главный объект экрана, занимает основную площадь. Минимум текста, минимум карточек на первом экране. Логика: сайт воспринимается как инструмент поиска, а не как лента для листания.

## B — Discovery-first (`b-discovery-first.jpg`)

Референс: Airbnb, Avito. Поиск — тонкая строка в шапке, не герой. Сразу под ней — карусели «Популярные направления» и «Курьеры с высоким рейтингом». Логика: пользователь пришёл посмотреть, что есть, а не сразу искать конкретный рейс — ставка на browsing и доверие через витрину проверенных курьеров.

## C — Trust-split (`c-trust-split.jpg`)

Референс: SkyPtoP, «Сквозняком», СДЭК. Кластер доверия («Верификация по паспорту», «Безопасная сделка») прямо над заголовком, до всего остального. Ниже — не единая форма поиска, а два равных пути: «Мне нужно отправить посылку» / «У меня есть место в багаже» — явно проговаривает двустороннюю модель рынка (курьер vs заказчик), чего нет ни в A, ни в B.

## Что не решено ни в одном варианте

Все три — это только «первый экран» (шапка + hero), без самой ленты объявлений ниже. Если один из трёх понравится по структуре, следующий шаг — доразвернуть его до полной страницы с лентой (как в `apps/web/src/app/page.tsx`), а не собирать с нуля.
